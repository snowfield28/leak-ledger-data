お知らせ全文
皆さま、こんにちは。Zeabur 創業者の Yuanlin Lin です。
本日は、難しい決断をお伝えしなければなりません。
Zeabur は段階的にサービスを終了いたします。2026年12月1日より一部のサービスを順次停止し、12月31日までにすべての専用サーバーと共有クラスターを終了します。
2度目のセキュリティインシデントから間もない中でこのお知らせを受け取ることは、さらなるご負担になることと存じます。サービスやデータへのご不安に加え、移行の計画まで必要になってしまいました。
この影響と、それによって生じる追加の作業は、私たちが負うべき責任です。今回の経緯、サービス終了を決めた理由、そして今後の対応についてご説明する前に、影響を受けたすべての皆さまに心よりお詫び申し上げます。
10月14日のセキュリティインシデントについて
2026年10月14日（UTC）、外部の攻撃者が Zeabur の内部システムおよび一部のお客様のサービスに不正にアクセスしました。異常を検知した直後から緊急対応を開始しています。今回のインシデントは、8月下旬のインシデントよりも影響範囲が広いことを確認しています。
現時点で、既知のすべての攻撃経路に対して封じ込め措置を講じ、引き続き不審な操作を監視しています。調査は継続中です。影響の全容と今後の対応については調査の進展に応じてお知らせし、後日より詳細な報告書を公開します。
短期間に再びセキュリティインシデントを起こしたことで、私たちを信頼してくださった皆さまの期待を裏切ってしまいました。お客様のサービスとデータを守ることは私たちの責任であり、それを果たせませんでした。
サービスに異常が見られる場合や、今回のインシデントの影響が疑われる場合は、Zeabur Support までご連絡ください。今回のインシデントにより損失を受けたお客様からの補償申請も、Zeabur Support で受け付けます。
サービス終了を決めた理由
Zeabur は誕生から約3年半が経ちました。この1年は最も大きく成長した時期であると同時に、その裏にある課題がはっきりと見えてきた時期でもありました。
n8n や OpenClaw から Vibe Coding まで、AI はクラウドデプロイにかつてない需要をもたらしました。一方で、AI によってデプロイそのもののハードルも急速に下がっています。私たちの成長は壁に突き当たり、Zeabur がユーザーに提供できる長期的な価値を改めて考え直す必要に迫られました。
また、このシステムは3年半前に短期間で開発したプロジェクトから始まり、市場のニーズに応えるためにアーキテクチャの変更や方向転換を重ねる中で、複雑さと保守の難しさが増していきました。今年後半に起きた2件のセキュリティインシデントによって、セキュリティと運用における私たちの不足がより明確になりました。
8月のインシデントの後、私たちは長い時間をかけて議論し、悩み続けてきました。今回のインシデントを受けて、事業を継続するために必要な投資と、チームが担える責任を改めて見直した結果、サービスを終了するという決断に至りました。
決断した以上、影響を受けるすべてのお客様にできるだけ早くお伝えし、移行のための時間をできる限り確保していただきたいと考えています。
今も Zeabur をご利用の皆さまにとって、これはサービスの移行やデータのバックアップ、場合によっては予定していた計画の見直しに時間を割くことを意味します。本来のお仕事に加えてこうした負担をおかけすることを、深くお詫び申し上げます。
サービス終了スケジュール
現時点で確定しているスケジュールは以下のとおりです。日付はすべて2026年です。
本日より
：専用サーバーとドメインの新規購入を停止し、アカウント残高の返金受付を開始します。
12月1日より（専用サーバー）
：更新機能を停止します。既存の専用サーバーは、12月1日から12月31日までの間、それぞれの有効期限に順次停止します。サーバーの有効期限をご確認のうえ、期限までにバックアップと移行を完了してください。
12月1日より（共有クラスター）
：稼働中のすべてのサービスを一時停止します。データのバックアップのため、手動で再開することは可能です。
12月31日
：すべての専用サーバーが期限を迎えて停止し、すべての共有クラスターの提供を終了します。
12月31日はプラットフォーム全体の最終終了日であり、すべてのサービスがその日まで稼働し続けることを意味するものではありません。
 ご利用のサービスとそれぞれの有効期限に合わせて、早めに移行をご計画ください。
特別な事情により上記のスケジュールでの移行が難しい場合は、できるだけ早く Zeabur Support までお知らせください。個別に対応策をご相談します。
データ、ドメイン、返金と補償
データの削除日、データエクスポートの最終期限、Zeabur Support の終了日は、まだ確定していません。確定し次第、改めてお知らせします。データ削除の期限が発表されるのを待たずに、上記のサービス終了スケジュールに沿ってバックアップと移行を進めてください。
Zeabur で購入したドメインは、セルフサービスでの移管が可能になっています。他のレジストラへの移管をサポートしますので、ドメインの移管も移行計画に含めてください。移管中に問題が発生した場合は、Zeabur Support までご連絡ください。
アカウント残高の返金と、セキュリティインシデントによる損失の補償は別々の申請で、どちらも Zeabur Support で受け付けます。ご連絡の際は、どちらの申請かを明記し、関連するアカウントやサービスの情報、問題の内容を添えてください。
未完了の案件の取り扱いについても、サポート体制に関する今後のお知らせでご説明します。
移行のサポートについて
今後、チームは今回のインシデントの調査、補償と返金の対応、そして皆さまのサービス移行の支援に注力します。
移行ガイド
を公開しました。これまで Zeabur が担ってきたことと移行後に補う必要があることを説明し、Claude Code や Codex などの Coding Agent が読める Markdown 版も用意しています。agent があなたの状況に合わせて移行を計画し、サポートします。今後も、よく使われているサービスや移行のケースを広くカバーできるよう更新していきます。
サービスごとにデータ、設定、デプロイ方法は異なります。移行の際には、バックアップが完全であることと、新しい環境で正常に動作することを必ずご確認ください。何から始めればよいかわからない場合や、途中で困ったことがあれば、Zeabur Support で状況をお知らせください。
この期間はサポートへのお問い合わせが増え、返信に通常より時間がかかる可能性があります。できる限り対応してまいります。ご連絡の際は、サービスが停止しているか、データにアクセスできないか、サーバーの有効期限はいつかをお知らせいただけると、緊急度を把握しやすくなります。
過去3年余りの間に Zeabur を支えてくださった皆さま、そして今もご利用いただいている皆さまに感謝いたします。ご自身のプロジェクトやプロダクト、そこに注いできた力を私たちに託していただいたことは、とても重い信頼でした。
今日の事態を防げなかったこと、そして Zeabur を続けられなかったことを、心よりお詫び申し上げます。これから私たちは、インシデントの事後対応と皆さまの移行の支援に真摯に取り組み、最後までしっかりと務めを果たします。
